# 非游戏内自动化测试收口审查

## 1. 功能与语义、架构设计

- 本轮收口的核心不是新增业务测试，而是把 Fabric 原版已有的非游戏内测试任务分层恢复到 NeoForge：`testStableCore / testIntegration / testClient / testSlow / testExtended` 均已重新接入构建脚本。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L157) [build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L218)
- `integration/client/slow` 三类扩展任务没有改测试源码语义，而是显式复用 NeoForge `forgejunitdev` 上下文：工作目录指向 `build/minecraft-junit`，并注入 `fml.junit.argsfile`、`fml.modFolders` 与 `@vmArgs.txt`，保持“平台差异只收口在测试基建层”的原则。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L166) [build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L188)
- `slow` 标签的性能口径没有通过修改测试源码默认常量来收口，而是仅在任务层用系统属性吸收 NeoForge 单测环境的偶发抖动，业务基线和原版测试源码仍保持一致。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L209) [LinkSavedDataPerformanceSlowTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataPerformanceSlowTest.java#L21)
- `client` 与 `integration` 标签源码本身没有被改写，只是被重新接回可执行入口，说明本轮通过依旧来源于测试运行环境收口，而不是断言降级。[ClientHooksContractTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/client/ClientHooksContractTest.java#L1) [LinkSavedDataIntegrationTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/integration/LinkSavedDataIntegrationTest.java#L1)

## 2. 关键数据结构和算法性能分析

- 本轮新增逻辑主要是 Gradle 任务编排，不引入新的业务数据结构。运行期开销来自测试任务准备与 NeoForge 启动参数注入，影响仅发生在测试阶段。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L188)
- `buildJUnitModFolders` 动态拼接 `main/test` 输出目录，确保扩展标签测试在 NeoForge JUnit 沙盒里能同时看到主代码与测试代码，复杂度线性且规模很小。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L169)
- 慢测性能用例的实测波动集中在 `load` 阶段边界，出现过 `48ms` 与 `26ms` 两种结果，说明影响因素主要来自 `forgejunitdev` 启动与 FML 初始化环境，而不是持久化算法出现确定性退化。[LinkSavedDataPerformanceSlowTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataPerformanceSlowTest.java#L58)

## 3. 数据流或调用链

- 默认稳定主线仍是 `test -> stable-core`；扩展主线则变为 `testIntegration/testClient/testSlow -> syncJUnitWorkspace + prepareNeoForgeTestFiles + forgejunitdev 上下文 -> 标签测试执行`。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L157) [build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L192)
- `test` 成功时，Gradle 会在 `build/minecraft-junit` 下启动 worker；本轮对扩展测试任务补齐后，它们也沿用同一调用链，不再落回普通工作区根目录，从而解决 `mainargs.txt` 缺失问题。
- 为避免共享 `build/minecraft-junit` 与 `build/test-results/testSlow` 时发生踩踏，测试任务被强制串行化，调用链顺序固定为 `test -> testIntegration -> testClient -> testSlow`。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L235)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面，本轮方案已经把 NeoForge 扩展标签测试的运行环境问题收口在构建脚本中，后续新增标签测试可以直接复用这一套上下文，不必重复在业务测试里写平台特判。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L188)
- 语义对齐方面，测试源码继续使用 `triggerSource/core`，方向仍是 `triggerSource -> core`，没有因为收口测试去引入旧术语或改写内部存储语义，校验结果为通过，残余语义风险为无。[LinkSavedDataIntegrationTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/integration/LinkSavedDataIntegrationTest.java#L23) [LinkSavedDataPerformanceSlowTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataPerformanceSlowTest.java#L45)
- 当前剩余风险主要是 Gradle/NeoForge JUnit 结果输出偶发 `in-progress-results...bin` 异常，这属于测试框架级波动。现阶段通过串行化任务与单独重跑已经规避；若后续频率升高，再考虑额外隔离各标签的结果输出目录或进一步禁用配置缓存。

## 5. 并发冲突审查

- 本轮没有新增业务共享状态，主要新增的是 Gradle 测试任务配置，因此业务并发风险低。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L157)
- 真正的并发冲突点出现在测试基建层：多个 `Test` 任务共享 `build/minecraft-junit` 沙盒与测试结果目录时，Gradle/NeoForge JUnit 可能互相踩踏。当前已通过 `maxParallelForks = 1` 和任务顺序约束显式降低该风险。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L160) [build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L235)
- 综合评估：共享状态风险低，读改写覆盖风险中到低，重入风险低。当前主要并发风险已从“任务共享沙盒导致结果文件异常”降到“框架级偶发波动”，风险等级为低。
