- 客户端入口继续沿用 `RedstoneLinkClient` 的原初始化顺序，兼容桥只负责把 NeoForge 事件翻译回 Fabric 风格回调，没有改动业务初始化语义。[RedstoneLinkClient.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/client/java/com/makomi/RedstoneLinkClient.java#L1) [ClientCompatBridge.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/net/fabricmc/fabric/impl/client/ClientCompatBridge.java#L56)
- `quick_link_tool` 资源态已按原版设计收敛为 `sd/cp` 两档，移除了历史 `visualize/vs` 独立模型态引用，避免 NeoForge 侧继续出现错误贴图引用，同时保留 `visualize` 观察流程本身的业务语义。[quick_link_tool.json](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/resources/assets/redstonelink/models/item/quick_link_tool.json#L1) [QuickLinkToolData.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/com/makomi/data/QuickLinkToolData.java#L1)
- 测试工程已经接上 NeoForge 主 classpath 和 JUnit 5，说明当前策略不是放弃原测试，而是优先恢复其在 NeoForge 下的执行基建。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L88)

## 2. 关键数据结构和算法性能分析

- 客户端兼容桥没有引入新的复杂缓存或调度结构，核心仍是事件转发，额外状态仅有 `registered` 与 `initialized` 两个布尔位，复杂度和运行期成本都很低。[ClientCompatBridge.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/net/fabricmc/fabric/impl/client/ClientCompatBridge.java#L30)
- `quick_link_tool` 模型态切换现在只保留 `custom_model_data = 0/1` 的分支，减少了不必要的资源分叉和模型查找，运行时路径也与 Fabric 原版当前设计保持一致。[quick_link_tool.json](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/resources/assets/redstonelink/models/item/quick_link_tool.json#L1)
- 测试接线通过 `testCompileClasspath.extendsFrom compileClasspath` 与 `testRuntimeClasspath.extendsFrom runtimeClasspath` 复用主工程依赖，避免为测试重复维护 Minecraft/NeoForge 依赖图，构建复杂度可控。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L88)
- `HideNodeDirectionalIntegrationTest` 中补齐 `Level` 的新抽象方法只影响测试夹具，不改变业务算法，也不会带来额外运行期负担。[HideNodeDirectionalIntegrationTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/integration/HideNodeDirectionalIntegrationTest.java#L1)

## 3. 数据流或调用链

- NeoForge 客户端启动后，经 `RedstoneLink` 注册客户端兼容桥，再由兼容桥按事件需要惰性调用 `RedstoneLinkClient.onInitializeClient()`，随后把渲染、按键、HUD、交互事件分发到 Fabric 风格 API 表面。[RedstoneLink.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/com/makomi/RedstoneLink.java#L1) [ClientCompatBridge.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/net/fabricmc/fabric/impl/client/ClientCompatBridge.java#L37)
- 测试任务当前调用链为 `JUnit test -> Bootstrap.bootStrap() -> Blocks/FeatureFlags -> FeatureFlagLoader.loadModdedFlags()`，在 `LoadingModList.get()` 为空时中断，因此失败点位于 NeoForge/FML 初始化前置，而非业务断言本身。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L142) [LinkRedstoneDustCoreStateContractTest.xml](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build/test-results/test/TEST-com.makomi.block.LinkRedstoneDustCoreStateContractTest.xml#L1)
- `QuickLinkToolDataTest` 等大批后续失败是由 `QuickLinkWorldOverlayRendererTest` 触发 `RenderType -> ItemRenderer -> Items -> Blocks` 级联初始化失败导致的 `NoClassDefFoundError`，表明现阶段应先修复统一运行环境，而不是逐个修改测试或业务类。[QuickLinkToolDataTest.xml](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build/test-results/test/TEST-com.makomi.data.QuickLinkToolDataTest.xml#L1)

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性风险当前集中在 NeoForge 测试运行环境而不是主工程。主工程、datagen、客户端冒烟与测试编译均已通过，说明迁移主体已经具备可运行骨架；后续应优先修 `test` 的 FML 初始化前置，避免误判为业务回归失败。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L88)
- 客户端兼容桥把多个 NeoForge 事件映射到 Fabric 风格回调，后续如果出现客户端运行期差异，优先继续在兼容桥收口，而不是回退 Fabric 业务设计。[ClientCompatBridge.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/net/fabricmc/fabric/impl/client/ClientCompatBridge.java#L42)
- 资源风险已下降。`fast_link_tool_vs` 缺图问题已经通过删除独立第三态模型引用收口，且不涉及贴图内容修改，只是清理失效模型引用路径。[quick_link_tool.json](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/resources/assets/redstonelink/models/item/quick_link_tool.json#L1)
- 建议下一阶段不要继续向普通 `test` 任务堆业务修补，而是先确认 NeoForge 官方 userdev/JUnit 的最小初始化方式，或将确实依赖完整模组加载的测试拆分到专门任务。

## 5. 并发冲突审查

- 当前改动主要集中在构建脚本、客户端兼容桥、注册接线、模型资源和测试夹具，写入面相对分散，内部没有新增共享可变状态热点。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L1) [ClientCompatBridge.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/net/fabricmc/fabric/impl/client/ClientCompatBridge.java#L30)
- `ClientCompatBridge` 中的 `register` 与 `ensureClientInitialized` 通过 `synchronized` 保证单次注册与单次初始化，线程边界明确，风险较低。[ClientCompatBridge.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/net/fabricmc/fabric/impl/client/ClientCompatBridge.java#L37)
- 测试失败不是并发冲突，而是统一的静态初始化缺口；因此当前并发风险等级为低，运行时初始化风险等级为中。
