# NeoForge 测试收口与最终验收审查

## 1. 功能与语义、架构设计

- 本轮收口没有改动业务层设计，而是在构建脚本中补齐 NeoForge 官方 `unitTest` 接线，使稳定核心测试在最小 FML 上下文中运行，继续保持“平台差异只收口在平台层”的迁移原则。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L45) [build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L87)
- `syncJUnitWorkspace` 只负责把 `src/main` 和 `src/test/resources` 同步到 `build/minecraft-junit/src`，兼容既有测试通过相对路径读取工程资源的方式，没有反向改动 `LinkSavedData` 等业务装载逻辑。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L105) [LinkSavedDataLoadCompatibilityTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataLoadCompatibilityTest.java#L205)
- 两份新增 SNBT fixture 直接按 Fabric 迁移原版口径补齐，保证兼容性测试验证的是原设计语义，而不是 NeoForge 侧临时构造的样本数据。[link_saved_data_invalid_dimension.snbt](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/resources/fixtures/nbt/link_saved_data_invalid_dimension.snbt#L1) [link_saved_data_missing_fields.snbt](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/resources/fixtures/nbt/link_saved_data_missing_fields.snbt#L1)
- 存档装载入口仍保持 `LinkSavedData.load(...) -> LinkSavedDataCodecSupport.load(...)` 的原有职责划分，说明本轮验收通过是测试基建收口的结果，不是业务语义改写的结果。[LinkSavedData.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/main/java/com/makomi/data/LinkSavedData.java#L93)

## 2. 关键数据结构和算法性能分析

- `unitTest` 接线本身不引入新的业务数据结构，影响面仅限 Gradle userdev 测试运行时，运行期性能成本可以忽略。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L87)
- `syncJUnitWorkspace` 使用 Gradle `Sync` 任务增量同步最小目录集，只复制 `src/main` 与 `src/test/resources`，避免把整个工程镜像到 JUnit 沙盒，构建开销和缓存失效率都可控。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L105)
- `LinkSavedDataLoadCompatibilityTest` 继续围绕异常维度、缺字段、非法链接序列号等边界做读取契约断言，复杂度主要取决于夹具规模；当前 fixture 很小，不会对测试时长形成压力。[LinkSavedDataLoadCompatibilityTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataLoadCompatibilityTest.java#L71)

## 3. 数据流或调用链

- 当前测试调用链变为 `Gradle test -> NeoForge unitTest 上下文 -> syncJUnitWorkspace 准备沙盒目录 -> JUnit stable-core 用例`，先解决平台初始化，再执行业务断言，顺序与问题根因一致。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L87) [build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L157)
- `LinkSavedDataLoadCompatibilityTest` 在运行时通过 `readFixture(...)` 读取 SNBT，再经反射进入 `LinkSavedData.load(...)`，最终验证 `triggerSource/core` 拓扑过滤结果；本轮没有改变这条验证链，只是确保其能在 NeoForge 测试沙盒里找到正确资源。[LinkSavedDataLoadCompatibilityTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataLoadCompatibilityTest.java#L75) [LinkSavedDataLoadCompatibilityTest.java](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/java/com/makomi/data/LinkSavedDataLoadCompatibilityTest.java#L214)
- 客户端最终验收沿用既有启动链：模组初始化、资源加载、客户端初始化、正常退出；本轮的测试收口没有再向客户端入口注入额外特判，说明客户端冒烟与测试基建是解耦收口的。

## 4. 安全、性能、兼容性、扩展性风险分析与建议

- 兼容性方面，本轮方案的核心优点是“读旧写新、业务不动、平台层吸收差异”。后续如果还要迁更多 Fabric 契约测试，应优先复用 `unitTest + syncJUnitWorkspace` 组合，而不是在每个测试里单独打补丁。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L87)
- 安全与语义风险较低。两份 fixture 都继续使用 `triggerSource/core` 术语，方向仍是 `triggerSource -> core`，没有旧术语写回内部存储或新文案，语义对齐结果为通过，残余风险为无。[link_saved_data_invalid_dimension.snbt](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/resources/fixtures/nbt/link_saved_data_invalid_dimension.snbt#L3) [link_saved_data_missing_fields.snbt](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/src/test/resources/fixtures/nbt/link_saved_data_missing_fields.snbt#L4)
- 唯一需要继续注意的是，若后续新增真正依赖完整游戏运行环境的测试，不应继续塞进普通 `test` 任务，而应明确拆到更合适的运行任务或专项回归流程。

## 5. 并发冲突审查

- 本轮代码改动集中在 `build.gradle` 和只读测试夹具，未引入新的共享可变业务状态，也没有修改任何多线程事件处理路径，因此并发冲突风险低。[build.gradle](/d:/OpenProjects/RedstoneLink/rl-neoforge-1.21.1/build.gradle#L105)
- `Sync` 任务发生在 Gradle 构建阶段，职责是准备测试沙盒目录，不参与模组运行期并发访问；运行时线程边界没有新增不确定性。
- 综合判断：共享状态风险低，读改写覆盖风险低，重入风险低，当前阶段主要风险已从“运行环境缺口”降为“后续若新增重型测试需继续合理分层”的流程性风险。
