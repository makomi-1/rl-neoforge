# NeoForge 扩展测试任务接线处置

## 阻塞点

- 直接在 NeoForge 工程里新增普通 `Test` 任务执行 `integration/client/slow` 标签时，测试进程会在启动前报 `mainargs.txt` 缺失。
- 根因是新建的 `Test` 任务没有继承 `test` 任务由 NeoForge `unitTest` 注入的 `forgejunitdev` 上下文，导致 worker 在错误工作目录中启动。
- 在共享 `build/minecraft-junit` 沙盒下，多个测试任务连续或交错结束时，还会偶发出现 Gradle `in-progress-results...bin` 丢失，属于测试框架级结果输出波动。

## 解决方法

- 为 `testIntegration / testClient / testSlow` 显式补齐与 `test` 一致的 NeoForge JUnit 上下文：
  - `workingDir = build/minecraft-junit`
  - `fml.junit.argsfile = build/moddev/junit/programArgs.txt`
  - `fml.modFolders = main/test 输出目录拼接`
  - `jvmArgs @build/moddev/junit/vmArgs.txt`
- 让扩展测试任务复用 `downloadAssets / writeNeoForgeTestClasspath / prepareNeoForgeTestFiles / syncJUnitWorkspace`，避免只拿到普通 JUnit 运行时。
- 为避免共享 `forgejunitdev` 沙盒踩踏，强制 `test / testIntegration / testClient / testSlow` 串行运行，并设置 `maxParallelForks = 1`。
- 对 `slow` 标签仅在任务层通过系统属性放宽 NeoForge 环境的慢测阈值，不修改测试源码默认常量。

## 复用建议

- 以后只要 NeoForge 新增标签测试任务出现 `mainargs.txt` 缺失，优先检查是否完整继承了 `forgejunitdev` 的工作目录、程序参数和 VM 参数。
- 以后只要多个 `Test` 任务共享 `build/minecraft-junit` 沙盒，默认按串行任务处理，不要假定普通 Gradle `Test` 任务可以安全并行复用同一游戏目录。
