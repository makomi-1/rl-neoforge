# NeoForge 测试沙盒兼容处置

## 阻塞点

- NeoForge 下普通 `test` 任务最初没有建立最小 FML 初始化环境，`Bootstrap.bootStrap()` 进入 `FeatureFlagLoader.loadModdedFlags()` 时会因为 `LoadingModList.get()` 为空而批量失败。
- 一批 Fabric 侧遗留契约测试直接使用 `Path.of("src/...")` 读取源码或 `src/test/resources` 夹具；NeoForge `forgejunitdev` 会把测试工作目录切到 `build/minecraft-junit`，导致这些相对路径在运行期失效。

## 解决方法

- 在 `build.gradle` 的 `neoForge` 配置中启用官方 `unitTest`，让测试任务进入 NeoForge 提供的最小模组加载上下文，而不是继续在裸 JUnit 环境里直接触发 Minecraft 静态初始化。
- 新增 `syncJUnitWorkspace` 任务，把 `src/main` 与 `src/test/resources` 同步到 `build/minecraft-junit/src`，只兼容旧测试对相对路径的读取方式，不改业务实现也不改原有断言语义。
- 对缺失的 SNBT fixture 直接按迁移原仓库 `D:\OpenProjects\RedstoneLink\rl-release-no-mixin` 原样补齐，避免为了适配测试去改存档加载逻辑。

## 复用建议

- 以后只要 NeoForge 单元测试出现 `LoadingModList.get()` 为空、`FeatureFlagLoader`、`Bootstrap.bootStrap()` 级联失败，先检查是否接入了官方 `unitTest`，不要先改业务代码。
- 以后只要旧测试通过 `Path.of("src/...")` 读取工程文件，而运行目录切到沙盒子目录，优先补同步层或统一测试资源入口，不要直接拟合测试结果去改实现语义。
